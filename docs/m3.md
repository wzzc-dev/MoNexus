# M3 — Workspace / Worktree / Files / Terminal

M3 adds a single workspace contract used for both local and SSH projects.
The desktop never learns which transport is in use: it holds a machine id
(`""` = local) plus an absolute root, and every file/git/terminal operation
goes through the same host RPC methods. Agent sessions and task scheduling
remain out of scope (M4/M5).

## Provider surface

`packages/providers/workspace` implements `WorkspaceProvider` as
`Local(LocalWorkspace)` or `Ssh(SshWorkspace)`:

- `list`, `stat`, `read_text`, `write_text`, `move`, `remove`
- `git_status`, `git_diff`
- `create_worktree`, `remove_worktree`
- `run_terminal`

Relative paths are normalized and reject absolute paths and `..` segments.
Writes use temp file + atomic rename on both transports (local `@fs.rename`,
SSH `mv -f` under a `trap`), with mode `0600` for the temp file. The SSH
provider reuses M2's `ssh_argv` and M0's `shell_quote`; remote commands are
fixed POSIX scripts with positional parameters, never interpolated paths.
Local terminals use a real PTY (`@pty.spawn`). Remote terminals run `ssh -tt`
behind a local PTY whose slave is put into raw mode before `exec`; resizing
that PTY sends SIGWINCH to `ssh`, which forwards the SSH `window-change`
request to the remote PTY. SSH container terminals use the same transport.
Interactive sessions attach to (or create) a tmux session, while one-shot
commands run directly so their output is not repainted by tmux.

## RPC methods

`workspace.open/list/listFiles/stat/read/write/move/remove/gitStatus/
gitDiff/close`, `worktree.create/remove/list`, `lease.acquire/release/list`,
`terminal.open/write/read/resize/close`. `workspace.list` lists open workspace
records; `workspace.listFiles` lists a directory inside one workspace.

Events: `workspace.opened/changed/closed`, `worktree.created/ready/archived`,
`lease.acquired/released`. Projections are rebuilt from those events at
startup (the same pattern as machines).

### Project membership RPCs

Project membership is an explicit Bot-to-Project relation, not a guess from
Chat participants:

- `project.membership.list` — optional `project_id`. An empty or omitted
  `project_id` returns every active membership; a non-empty one filters by
  Project. The result is `{"memberships":[...]}` and only contains rows in
  `MEMBERSHIP_STATE_ACTIVE`.
- `project.membership.add` — `project_id`, `bot_id`, optional `actor`
  (default `owner`). The host checks that the Project exists and that the Bot
  exists and is not archived, then stores an active membership with
  `access=[]`. Re-adding an active membership returns the existing row and
  emits no second `project.member.added` event. A previously removed row is
  restored through the membership transition rules. The result is
  `{"membership":{...}}`.
- `project.membership.remove` — `project_id`, `bot_id`, optional `reason`
  and `actor`. It follows the existing transition rules and returns the
  removed membership. Removal is rejected as `conflict` while the Bot still
  has a non-terminal AgentSession in that Project; ending the session makes
  removal possible again. Unknown Bots/Projects/memberships map to
  `not_found`, missing parameters to `invalid`, and stored/transition
  rejections follow `bots_error_from_message`.

Events are `project.member.added` and `project.member.removed`. `ProjectRecord`
has no archive state, so "Project exists" is the only Project precondition.
M1 deliberately stores an empty access list; effective permissions remain the
Bot ceiling plus `bots_permission_snapshot`, so adding a member never changes
a permission ceiling.

## Bookkeeping rules

- A git project is opened as a workspace; runs get host-created worktrees via
  `git worktree add`.
- A non-git directory uses a workspace lease instead.
- `leases` has a UNIQUE `(target_kind,target_id)` index, and the host checks
  for an existing lease under its mutex before appending `lease.acquired`.
  At most one active run therefore holds a worktree or non-git workspace.
- Closing a workspace is refused while it has an active lease or live
  worktrees; removing a worktree is refused while it is leased.

## CLI

A generic authenticated RPC command is available for shell tests:

```bash
HOST=_build/native/debug/build/monexus/host/host.exe
$HOST rpc --method workspace.open --params '{"target":"local","root":"/tmp/proj"}'
$HOST rpc --method workspace.listFiles \
  --params '{"workspace_id":"wsp_...","path":""}'
```

`client_request_id` is added when the JSON object does not carry one.

## Desktop

The Projects page has a machine-id/root open form, a file tree, a text-area
editor with Save, git status/diff panes, a terminal transcript/input panel,
and worktree branch/path creation. Selecting a Project also exposes its active
Bot members with Remove and Add controls by Bot name; the same controls appear
on the Bot page's Project section. The selected workspace can open a focused
terminal surface with a selectable, scrollable transcript, a visible prompt,
command history, interrupt/clear/close/reconnect controls, and live output
polled from the host byte cursor while the session is open. The worktree list
is only summarised.

## Verification

```bash
moon build --target native
moon test  --target native        # 53 tests
scripts/host_smoke.sh             # M1 regression
scripts/machine_smoke.sh          # M2 regression
scripts/workspace_smoke.sh        # M3: 107 checks, native harness
```

`workspace_smoke.sh` covers local open/list/read/write/stat/move/remove,
git status/diff, two parallel worktrees with isolated writes, lease
conflicts/release, PTY terminals, restart replay, and the same contract over
an ephemeral loopback sshd (list/read/write/stat/diff/terminal/worktree).
The script is a thin shell wrapper around `services/smoke-harness`; shell owns
the temp HOME/state, fixture repository, ephemeral sshd and host lifecycle,
while the native MoonBit harness performs all typed RPC/JSON assertions and
prints the PASS/FAIL/SKIP summary. The SSH section uses a temp HOME, temp keys
and an explicit temp known-hosts file; the script snapshots the real `~/.ssh`
before/after and asserts it was not modified. jq is not required. sshd, ssh
and tmux are required for the SSH section; it is skipped when they are
unavailable.

## Known M3 limitations

- No large-file streaming/chunking or recursive tree walking; list is one
  directory level, reads are whole-file and diffs are truncated at 128 KiB.
- The focused desktop terminal polls live output with cursor-based reads and
  propagates resize to local, SSH and environment PTYs; plain Ctrl+C (or Stop)
  interrupts and Cmd+C / Ctrl+Shift+C / Ctrl+Insert copy in both the focused
  and floating terminal surfaces, and the worktree list is summarised rather
  than displayed as a management table.
- Remote interactive tmux sessions are not explicitly killed by host close;
  the smoke test sends `exit` to avoid leaving a detached session.
- No `workspace.changed` watcher: events are emitted only for host-mediated
  writes, moves and removes.
- The generic `rpc` CLI takes wire field names, not the typed builders used by
  the desktop/CLI machine commands.
- Full-cursor event replay (`events.subscribe --since`) is still limited by
  the 256-event in-memory ring inherited from M1.
