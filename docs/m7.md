# M7 — packaging, one-command startup and first run

M7 makes V0.1 runnable from the README: a single `monexus` command starts or
reuses `monexus-host`, reads `host.json`, and opens the desktop; a release
tarball with a fixed install layout and SHA-256 is produced by
`scripts/package.sh`; the first run initializes `~/.monexus` with a sample
Workspace; and `scripts/acceptance.sh` proves the V0.1 flows end to end under
a throwaway `HOME`.

The architecture/implementation deviations (host-first launcher, additive
local machine kind, first-run layout, packaging/version) are recorded in
[ADR-0010](adr/0010-m7-launcher-packaging.md).

## What M7 adds

- **Launcher** — `scripts/monexus.sh` / installed `bin/monexus`:
  `start` (default), `status`, `stop`, `version`, `host <args>`; flags
  `--headless`, `--state-dir`, `--no-keep-alive`; installed and repo layouts;
  single-instance check via `host.status` + `host.lock`; detached host with
  keepAlive; clear exit-3 message and headless/xvfb hint when no display.
  `scripts/start.sh` delegates to `monexus.sh start`.
- **Packaging** — `VERSION` (0.1.0) + `packages/contracts/version.mbt`
  agree; `scripts/package.sh` builds `moon build --target native --release`,
  checks the fixed product paths, stages `bin/` + `share/monexus/`, verifies
  the staged launcher and component `--version`, and writes
  `dist/monexus-0.1.0-<os>-<arch>.tar.gz` + `.sha256`.
- **First run** — the host creates `agents/`, `artifacts/`, `logs/`,
  `monexus.db` and `examples/hello-workspace` (README, AGENTS.md, best-effort
  git repo) before publishing `host.json` (0600); existing files are never
  overwritten.
- **Settings** — the Settings page shows connection, host address, token
  status (present/missing, never the value), version, data directory, host id
  and last error, plus Light/Dark appearance and English/中文 language controls;
  both preferences are saved locally for the next launch.
- **Docs** — rewritten README (install → start → machines → workspace →
  agent → tasks/approvals → recovery → limitations), `docs/usage.md`,
  `docs/troubleshooting.md`, this note, ADR-0010.
- **Acceptance** — `scripts/acceptance.sh`: fresh `HOME`, packaged install,
  local + loopback SSH machines, mock ACP, parallel evidence-gated Runs,
  Decision waive/retry/fail, desktop reconnect under xvfb, host SIGKILL +
  reconcile, fake-SSH unreachable → `lost`/`unverifiable` + recovery Decision,
  audit and secret checks. PASS/FAIL/SKIP table plus summary; non-zero on
  failure.

## How to reproduce

```bash
export PATH="$HOME/.moon/bin:$HOME/.nvm/versions/node/v26.13.0/bin:$PATH"
scripts/acceptance.sh

# faster, without re-packaging:
ACCEPTANCE_SKIP_PACKAGE=1 scripts/acceptance.sh

# debug leftovers:
KEEP_ACCEPTANCE_WORK=1 scripts/acceptance.sh

# opt-in real ACP probe (needs Node + login + first npx download):
M7_REAL_ACP=1 scripts/acceptance.sh
```

`acceptance.sh` builds/stages the tarball in its temp work dir, verifies its
SHA-256, unpacks it and drives the installed `bin/monexus*`. External
machines are replaced, not contacted:

- **SSH**: a temporary non-root sshd on a random `127.0.0.1` port with
  temporary host/client keys and a temporary known-hosts file; the real
  `~/.ssh` is asserted untouched.
- **Unreachable SSH**: a fake `ssh` on `PATH` that executes locally and can
  be switched to `disconnect` (exit 255) through a mode file.
- **Desktop**: real native window under `xvfb-run` when no physical display
  exists, with `MONEXUS_LINK_TRACE=1` and `stdbuf -oL` so live link
  transitions are observable.

Verified run (2026-11-25, Linux 6.8 x86_64, xvfb-run/scrot present, Node
v26.13.0, MoonBit at `~/.moon/bin`):

```
SUMMARY  checks=69 failed=0  result=PASS
```

The 69 checks include packaging P0 (two rows), a1–a8, b1–b6, c1–c5, d1–d5
(plus opt-in d6 SKIP), e1–e8, f1–f9 (f5/f5b), g1–g7, g8/g8b, g9–g12 and
h1–h11. The full row-by-row output is printed by the script; the
requirement-level result is below.

### macOS (verified separately, 2026-11-27)

macOS support was added after the 69-check Linux run. On **macOS aarch64**
(Apple Silicon, macOS 26.3 / Darwin 25) the following were verified separately:

- `moon build --target native` (debug) and `--release`: 0 errors, both the
  Linux `linux_skia` and macOS `macos_skia` desktop entries;
- `moon test --target native`: **524/524 passed** (Docker and live-credential
  rows skipped by their opt-in gates);
- `scripts/package.sh`: `dist/monexus-0.1.0-macos-aarch64.tar.gz` (13 MB)
  plus a `shasum -a 256` checksum, and the staged `monexus version` /
  `--help` / `monexus-desktop --version` checks;
- `scripts/host_smoke.sh`: PASS (host.json mode 600, status online,
  heartbeat, flock rejection, 401);
- the installed launcher: `start --headless` → `status` online → `stop` rc 0;
- the installed `monexus-desktop`, launched from a logged-in GUI session
  against that host: process alive after 4 s with `link online` traced (window
  controls were not driven automatically).

`acceptance.sh` still depends on a loopback sshd and `xvfb-run`, so its 69
checks remain Linux-only. The macOS runner has no GUI session, so the macOS
desktop entry is built but the native window is not launched in CI; use a
logged-in GUI session for window use. Ubuntu and macOS x86_64 were not
separately exercised.

### Real remote machine (verified separately, 2026-11-25)

`acceptance.sh` keeps its loopback sshd and fake-ssh substitutes; it does not
contact the real remote machine. A real **Debian 13 x86_64** machine was
verified separately on 2026-11-25:

- `machine add` plus probe: machine online with a Linux x86_64 profile;
- remote workspace: file read/write, git and terminal;
- one task with parallel local + remote Runs: `2/2 runs succeeded`, and every
  evidence row was verified.

Scope: **Debian 13 x86_64 is verified. Ubuntu has not been separately
verified — do not describe the Debian result as Ubuntu. RISC-V is out of V0.1
scope.**

### Real ACP (verified separately, 2026-11-25)

`@zed-industries/claude-code-acp 0.16.2` was verified with a logged-in
account: the readiness probe passed, and one real turn streamed the requested
output with `stop_reason=end_turn`. This was local to the host machine; agent
sessions remain **local-only in V0.1**. The `d6` row itself stays opt-in
(`M7_REAL_ACP=1`) and was SKIP in the recorded 69-check run.

## Leftover / not covered by M7

- Packaging is verified on Linux x86_64 and macOS aarch64; the launcher is
  POSIX shell and the native entries are `linux_skia` (Vulkan/Wayland/X11) and
  `macos_skia` (AppKit). macOS x86_64 was not separately exercised. No Windows
  build, installer, signing or auto-update.
- The acceptance script itself uses a loopback sshd and a fake-ssh fault
  injector; it does not contact the real remote machine. A real **Debian 13
  x86_64** machine was verified separately: machine add/probe online with a
  Linux x86_64 profile, remote workspace read/write/git/terminal, and parallel
  local + remote Runs `2/2 runs succeeded` with every evidence row verified.
  **Ubuntu has not been separately verified; do not describe the Debian result
  as Ubuntu.** RISC-V is out of V0.1 scope.
- The real ACP adapter is only probed by acceptance when `M7_REAL_ACP=1`, a
  login exists and the first npx download succeeds; otherwise the row is SKIP.
  A separate 2026-11-25 check with `@zed-industries/claude-code-acp 0.16.2`
  passed readiness and one real turn (`stop_reason=end_turn`); agent sessions
  remain local-only.
- The desktop recovery scenario uses `xvfb-run` (no physical display) and
  terminates the process group as the window-close equivalent; it does not
  drive a compositor/window-manager close event.
- `unverifiable` Runs are never auto-retried by design; the owner must answer
  the recovery Decision. Retrying may duplicate side effects.
- A host restart during `verifying` marks the Run unverifiable rather than
  re-entering the gate; evidence is not replayed.
- Packaging does not include a service manager or OS integration; `monexus`
  is a user-level launcher and state lives in the user's `~/.monexus`.
