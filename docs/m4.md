# M4 — Agent Sessions (ACP) / Permission Decisions / Agent Home

M4 adds the first agent vertical slice. A session starts a real ACP
(Agent Client Protocol) stdio adapter on the host, streams its output to the
desktop, turns `session/request_permission` into a pending `Decision`, and
resumes the same ACP session after the owner answers. Task/Run scheduling is
still out of scope (M5).

The M0 spike (`spikes/m0`, Apache-2.0 MoUI reference) is reused as a protocol
reference; the provider is a MoNexus original written against the same ACP
shape.

## Provider surface

`packages/providers/agent` implements one ACP stdio sidecar per session:

- `probe_agent(spec)` — resolve the executable, spawn, `initialize` +
  `session/new`, classify auth-looking failures. Readiness is recorded even
  when it fails.
- `spawn_agent(group, spec)` — newline-delimited JSON-RPC 2.0 over
  stdin/stdout; raw malformed stdout lines surface as transcript lines.
- `AgentProcess::request` — one request/response with unsolicited
  agent→client requests answered (`cancelled` for permissions, `-32601`
  otherwise) so the adapter never hangs during the handshake.
- `acp_initialize`, `acp_new_session`, `acp_load_session`, prompt/permission
  payload helpers.

`@process.spawn` does not search `PATH`, so the provider resolves the command
to an absolute path and wraps it with `/usr/bin/env -u CLAUDECODE ...`. M0
found the real adapter refuses to start when Claude Code's own `CLAUDECODE`
marker is inherited. The default command is `npx -y
@zed-industries/claude-code-acp@0.16.2` (the version verified in M0); a bare
`node` + script pair can be passed instead for the mock/test adapter or any
other ACP implementation.

The documented fallback is `mode: "stdout"`: the same spawn/read machinery,
raw stdout lines appended to the transcript, EOF finalizing the session. It
has no protocol handshake and no turn-completion signal.

## RPC methods

`agent.probe/start/send/read/stop/list/resume/memoryRead/memoryWrite` and
`decision.list/respond`. `agent.read` is cursor-based and also returns the
projected state and the first pending decision id. `agent.start` accepts an
explicit `workspace_id`/`worktree_id`/`cwd`; M4 only runs agents in **local**
workspaces and rejects SSH-backed ones.

Events: `agent.readiness.ok/failed`, `agent.session.started/updated/output/
stopped/exited/resumed`, `agent.artifact.created`, `agent.memory.updated`,
`decision.requested/responded/expired`. Every event carries the full record
so a reconnect can rebuild the page without another request.

## Permission → Decision → ACP

A `session/request_permission` arriving on the session pipe becomes a
`Decision` of kind `permission`:

- the decision detail is the ACP tool call JSON, options are the ACP
  `optionId`/`name`/`kind` triples;
- the session record moves to `waiting_decision`, and the ACP reply id is
  held in the runtime's pending map;
- `decision.respond` claims the pending entry (double answers are refused),
  writes `{"outcome":{"outcome":"selected","optionId":...}}` (or `cancelled`)
  to the same stdio pipe, persists `decision.responded`, and moves the state
  back to `running`.
- readiness failures use the same channel with kind `readiness` and no
  options; a free-text answer is enough.

Nothing is auto-approved. If the session ends or the host restarts first, the
decision expires.

## Agent home, memory and artifacts

Each agent id has a host-managed home:
`<state_dir>/agents/<id>/` with `AGENTS.md` (written once, mode `0444`,
read-only in the UI/RPC), `MEMORY.md` (mode `0644`, writable through
`agent.memoryWrite` only), and `artifacts/` (mode `0700`).

`agent.start` prefixes the first prompt with a capped block:

```
[MoNexus agent context]
--- AGENTS.md (read-only) ---
...
--- MEMORY.md ---
...
[/MoNexus agent context]
```

The cap is `memory_limit` (default 4096, max 16384) shared by both files; the
record reports `memory_bytes` and `memory_injected`. Every MEMORY.md write
emits `agent.memory.updated` with actor, size and a content digest — sessions
cannot silently rewrite it. On session end the host diffs MEMORY.md against
the snapshot taken at start and, when it changed, writes a `text/x-diff`
artifact under `<home>/artifacts/<session_id>-memory.diff` (mode `0600`) and
records `agent.artifact.created`. `AGENTS.md` is never rewritten.

## Resume and restart

`agent.resume` requires ACP mode with a non-empty `acp_session_id` and
`loadSession: true` from `initialize`. It spawns a fresh adapter and calls
`session/load`; the session record emits `agent.session.resumed` and returns
to `idle`. Resuming a live session returns its projected record
idempotently.

ACP processes do not survive a host exit. At startup the host marks every
still-active session `exited` with `stop_reason=host_restarted`, expires all
pending decisions, and then serves clients. Finished transcripts are kept in
memory (up to 64 sessions) so `agent.read` still shows the last output after
a stop; they are not persisted across a host restart.

## Desktop

`Agents / Sessions` starts a session against an agent id, mode, workspace or
worktree id and an initial prompt; it shows the live transcript, follow-up
input, Stop/Resume, and the recent-session list. `Inbox` lists pending
decisions with one button per ACP option plus a free-text answer field. The
stream worker polls `agent.read` every 300 ms on a short-lived connection, so
long-lived event notifications are never blocked. Readiness-failure
decisions appear in the same Inbox.

## Test doubles

`tests/agent/mock_acp_agent.mjs` is a minimal ACP stdio agent used only by
the smoke test: it streams chunks/thoughts, echoes markers when the injected
context is present, sends one permission request when the prompt says
"permission" and waits for the client's answer, can fail `initialize` with an
auth-looking error, and advertises `loadSession`. `tests/agent/
mock_stdout_agent.mjs` prints three lines and exits. Neither is part of the
product critical path.

## Verification

```bash
moon build --target native
moon test  --target native        # 53 tests
scripts/host_smoke.sh             # M1 regression
scripts/machine_smoke.sh          # M2 regression
scripts/workspace_smoke.sh        # M3 regression
scripts/agent_smoke.sh            # M4: 80 checks (mock ACP full chain)
M4_REAL_ACP=1 scripts/agent_smoke.sh   # + one real adapter readiness probe
```

`agent_smoke.sh` uses a temp state dir and temp `HOME`; the SSH-related test
doubles never touch the real `~/.ssh`. It covers:

- probe ok + auth-looking failure → `agent.readiness.failed` + a readiness
  Decision answered in the Inbox;
- `AGENTS.md` mode `0444` and refused writes; audited `MEMORY.md` writes;
- start with memory injection, streamed message/thought chunks, cursor
  reads, follow-up `agent.send`;
- permission → pending Decision → inbox answer → ACP reply → the same turn
  continues;
- stop → memory diff artifact (mode `0600`) appended to the session record;
- resume via `session/load` and a new turn on the resumed session;
- raw stdout fallback and EOF finalize;
- hard host crash → `host_restarted` session close + expired decision;
- the full event set replays from SQLite.

The real adapter was verified once in this workspace (logged-in account):

- readiness probe: PASS, `@zed-industries/claude-code-acp 0.16.2`,
  `loadSession=true`, protocol version 1;
- one session with `prompt: "Reply with the single word OK."`: streamed `OK`,
  state `idle`, `agent.stop` acknowledged.

## Known M4 limitations / leftovers

- **Local agents only**: `agent.start` rejects SSH-backed workspaces and
  worktrees. Remote agent hosting now has a transport decision — ACP over
  `ssh -T` stdio in [ADR-0011](adr/0011-agent-over-ssh.md) — but it is
  PoC-only; V0.1 sessions stay local.
- **No Task/Run scheduling**: sessions are started by hand from the desktop
  or `rpc`; M5 owns the scheduler, leases and queue.
- Transcripts are in-memory. A finished transcript survives a stop/resume in
  the same host lifetime but not a host restart; only session records,
  decisions and artifacts are persisted.
- Desktop streaming is polling (300 ms), not server push; the event stream
  does carry state changes but the transcript is read by cursor.
- The stdout fallback has no handshake, no turn completion and no readiness
  beyond "executable found"; it is a compatibility escape hatch.
- `AGENTS.md` is created from a fixed template; there is no editor for it
  because it is defined as read-only. MEMORY.md is the only writable file.
- Permission answers must come from `decision.respond`; there is no
  auto-approve policy and no timeout-based approval in M4.
- Real adapter runs need a logged-in agent account on the host machine and
  network access to `npx` on first use; model credentials never enter
  events, logs or artifacts.
- Artifacts have no read RPC yet; the event carries the file path and the
  session record carries the artifact id.
