# MoNexus V0.2 最小范围计划（草案）

- 版本：0.1（基于架构 r5）
- 日期：2026-11-25
- 状态：**待 owner 定稿**。本文给出 D8/D9 的评审结论、边界条件与 V0.2 最小范围的依赖顺序；D8/D9 的最终决定以 owner 更新 `docs/architecture.md` 为准。
- 依据：`docs/architecture.md` §6、§8、§9、§11、§16–§18；V0.1 已完成本地 + SSH 的真实多机工作台，远程 Agent 的 `ssh -T` PoC（ADR-0011）已验收。

## 1. 评审结论

### 1.1 D8：V0.1 SSH 直连、V0.2 配对 runtime + 环境配方

**结论：有条件通过（Approve with boundaries）。**

方向正确：V0.1 用系统 `ssh` 做基线，成本低、可审计、能覆盖第一台远程机；V0.2 再引入配对 runtime，解决 NAT/弱网、远端常驻执行与断线恢复；环境配方作为 WorkspaceProvider 的一种实现，避免把容器/云沙箱塞进 host 主流程。前提是以下边界先固定：

1. **SSH 直连不退役**：V0.2 的配对 runtime 是 opt-in 的第二种执行方式；SSH 仍是引导、回退与故障排查通道，V0.1 的机器/Workspace/Run 行为不能被改写。
2. **远端 runtime 是执行面，不是第二控制面**：组织、成员、任务、Decision、审批结果与审计的权威仍在主控 host。远端 host 只持有受控的本地策略快照与执行事件签名，不独立创建 Task/Decision，不接受第二套审批。两套状态冲突时以主控事件日志为准，远端状态可丢弃重建。
3. **配对是信任建立，不是集群成员**：一次性短时配对码 + 双向密钥/证书校验；支持吊销、轮换与按机器 scoped token；不要求入站端口，默认由远端向外连接。
4. **ACP 不进入 MachineProvider**：`kind=runtime` 仍只提供 probe/exec/pty/心跳等执行能力；ACP 属于 AgentRuntime。远端 ACP 的启动/通信继续由 AgentRuntime 负责（可经远端 exec 启动，或后续由远端 AgentRuntime 适配器承载），不能把 ACP 句柄塞进 MachineProvider。
5. **策略在执行端判定，批准在主控端**：远端 host 对高风险命令做策略检查；需要人工审批时回到主控 Decision。主控不可达时高风险操作只能等待或明确 `unverifiable`，不得离线放行。
6. **环境配方最小实现只做一个后端**：V0.2 先做 Docker（本机或远端 runtime 上的容器），不做 VM/云沙箱编排；配方必须可版本化、可签名、生命周期脚本可审计，失败/取消有明确清理，不能让容器或临时目录泄漏。
7. **事件与幂等先行**：远端执行必须使用稳定 `run_id`/`session_id`，重连后按游标补事件并去重；断线不能制造“重复执行”或“假成功”。

满足以上条件后，D8 可以作为 V0.2 的正式决策。

### 1.2 D9：每 Agent 独立 home + AGENTS.md/MEMORY.md 摘要注入

**结论：通过（Approve with guardrails）。**

V0.1 已经把 Agent 身份做成跨 Run 的长期对象，并用有界摘要注入降低上下文成本；这比在每轮会话里塞完整记忆更可控，也为 V0.2 技能包留下清晰边界。需要固定以下护栏：

1. **隔离与权限**：每个 Agent 的 home 独立（`agents/<agent_id>/`，目录 0700），不得跨 Agent 读取；`AGENTS.md` 对会话只读；`MEMORY.md` 只能经 host 工具写入，写入与快照进审计。
2. **注入是有界、确定性的**：摘要按固定优先级与体积上限（默认 4 KB，可配置上限 16 KB）截断；不注入密钥、token、完整环境变量或大段日志；内容明确标记为 Agent/用户内容，不得被当作系统指令执行。
3. **记忆可审计、可清理**：Run 结束时做快照并生成 `memory_diff` Artifact；保留策略与 GC 明确；owner 可查看、清空、按 Agent 删除；记忆不自动跨 Agent 合并。
4. **记忆不等于能力**：记忆内容不能授予工具、审批豁免或策略例外；技能包是独立对象，不能靠往 MEMORY.md 写一段文字获得权限。
5. **技能包后置**：V0.1 只保留 AGENTS.md 约定，不加载技能；V0.2 技能包必须有 manifest、版本、权限声明、按 Agent/Task 启停与审计，且不得绕过 §11 的风险策略。

满足以上条件后，D9 可以作为 V0.2 的正式决策；技能包的实现细节应在 V0.2 单独写 ADR/设计，不在 D9 里预支。

## 2. V0.2 最小范围与依赖顺序

V0.2 只做五件事，按依赖排序。A1 是硬前置；A2 与 A3 可在 A1 后并行；A4 依赖 A1/A3 与 D9 的稳定记忆接口；A5 最后，因为它同时依赖 runtime、策略与 readiness。

| 阶段 | 项目 | 依赖 | 最小交付 |
|---|---|---|---|
| A1 | 配对远端 runtime | V0.1 完成 | `monexus-host` 远端运行、配对码接入、执行/终端/事件/重连 |
| A2 | 环境配方 | A1 | 一个 Docker 后端的 recipe 生命周期与 Workspace 集成 |
| A3 | 触发器 | A1 事件模型 | 事件/日程/webhook 触发 Task，幂等、限流、可停用 |
| A4 | 技能包 | A1 + A3 + D9 | 版本化技能 manifest、按需加载、权限与审计 |
| A5 | 账户托管 | A1 + 策略 + readiness | keychain/0600 托管、代理注入、按机器/Agent 授权、吊销 |

### 2.1 A1 配对远端 runtime（最先）

**范围**：在主控 host 之外增加一个远端 `monexus-host` 执行节点；通过一次性配对码建立双向认证通道，远端执行命令、PTY、Workspace 文件操作与事件上报。SSH 直连继续保留。

**验收标准**：

- 两台机器（一台主控、一台远端）在无入站端口、NAT/弱网条件下完成配对；配对码短时有效，错码/过期/重放被拒绝；可主动吊销并立即断链。
- `kind=runtime` 的机器可 probe 出 profile；在远端 Workspace 执行命令，stdout/stderr 分流、退出码与超时正确，事件带稳定 `run_id`。
- 断线后重连：远端 Run 继续，主控按游标补齐事件；同一 `run_id` 不重复执行，不出现重复结算，不把断线当成功。
- 主控不可达时，高风险命令停在等待/`unverifiable`；恢复后回到同一 Decision，不能离线放行。
- 同一台机器的 SSH 直连路径仍可正常注册、执行与恢复；runtime 与 ssh 两种方式互不污染状态。
- 审计可查：配对、吊销、远端执行、审批、断线/恢复都有事件；日志与事件不含凭据。

**非目标**：不做多主控、集群选主、跨 runtime 迁移、远端独立组织/审批。

### 2.2 A2 环境配方

**范围**：WorkspaceProvider 增加 recipe 生命周期；V0.2 只实现 Docker 后端（本机或 A1 的远端 runtime），用于一次性工作环境。

**验收标准**：

- recipe 有 name/version/image/mount/lifecycle/doctor 字段；未知或未签名 recipe 被拒绝；版本变化可审计。
- `createEnvironment` 成功返回句柄，Workspace 能在其中读写、git、运行命令；`destroyEnvironment` 清理容器、挂载与临时目录。
- 启动失败、命令取消、宿主异常三种场景都不留孤儿容器/目录；doctor 能给出可读诊断。
- 高风险生命周期脚本（安装、privileged、宿主挂载）进入审批；脚本与输出有审计。
- 一个 recipe 创建/使用/销毁的完整 e2e 测试通过，且不影响同机 SSH/本地 Workspace。

**非目标**：VM、云沙箱、K8s、Coder/Terraform 集成；配方市场。

### 2.3 A3 触发器

**范围**：Trigger 对象（事件、日程、webhook）创建 Task/Run；事件来自 host 事件流，webhook 只接受签名/白名单来源。

**验收标准**：

- 触发器可创建、停用、过期；事件触发只产生一次 Task（重放/重复 webhook 不重复创建）；有幂等键与去重窗口。
- 日程触发按机器时区/显式 UTC 运行，错过的窗口有明确补跑/跳过策略。
- webhook 校验签名与来源 allowlist，拒绝重放与过期请求；速率限制有界。
- 触发出来的写操作仍按 §11 风险策略走审批；触发器不能绕过 Decision。
- 审计含触发来源、幂等键、Task/Run 关联；停用后不再产生新 Run。

**非目标**：常驻可视化工作流编辑器、跨组织触发器、任意脚本执行。

### 2.4 A4 技能包

**范围**：按需加载的技能包（渐进披露），供 Agent 在 Task/会话中启用；技能是声明式的说明/脚本/资源包，不是特权通道。

**验收标准**：

- 技能有 manifest（名称、版本、权限、入口、依赖）、内容哈希与来源；未签名/未 allowlist 的技能不能加载。
- 技能按 Agent/Task 显式启用；未启用时不出现在上下文、不可调用；停用后新会话不再加载。
- 技能声明的权限不超过当前 Agent/策略的允许集；高风险步骤仍进审批；技能不能读取其他 Agent 的 home 或凭据。
- 加载/启停/调用有审计；版本固定，升级需显式变更；卸载不残留可执行入口。
- 至少一个只读诊断技能与一个写入技能（写入必须走审批）的 e2e 通过。

**非目标**：技能市场、任意远程代码下载执行、自动授予工具。

### 2.5 A5 账户托管

**范围**：host 托管 Agent 账户/模型凭据（keychain 或 0600 文件），通过环境变量注入或本地代理提供给 Agent；凭据不进入 Workspace、事件、日志或快照。

**验收标准**：

- 凭据只在 keychain/0600 存储；事件、日志、Artifact、Decision、会话记录中不出现明文；现有 redaction 测试扩展覆盖。
- 按机器与 Agent 绑定授权；未授权 Agent/机器拿不到凭据；吊销/轮换后旧凭据立即失效。
- 远端 runtime 上的 Agent 通过托管通道获得访问，但 Workspace 内不可见、不可复制；子进程继承范围受控。
- readiness 在启动前检查托管账户是否可用；失败生成可读 Decision，不反复重试。
- 一个真实模型调用的 e2e 通过，并证明 token 不出现在任何持久化面；撤销后同一调用失败关闭。

**非目标**：多租户账户池、第三方 OAuth 代理、跨组织共享凭据。

## 3. 依赖关系

```text
A1 配对远端 runtime
 ├─ A2 环境配方
 ├─ A3 触发器
 │    └─ A4 技能包（还需 D9 记忆接口稳定）
 └─ A5 账户托管（还需策略与 readiness 稳定）
```

- A1 必须先完成；A2/A3 可在 A1 验收后并行。
- A4 不应早于 A3：技能需要稳定的触发/会话上下文与审计链；同时依赖 D9 的 per-Agent home 与有界记忆接口。
- A5 最后：它把凭据托管、策略与 readiness 串起来，任何前置不稳都会把风险放大到所有 Agent。

## 4. D8/D9 边界（写入正式决策）

### 4.1 D8 边界

- V0.1 SSH 直连与现有三轴架构不变；V0.2 runtime 是可选执行节点，不替换 SSH。
- 主控 host 是唯一控制面与审计权威；远端 runtime 只执行、上报、按策略快照判定，不拥有组织/任务/审批状态。
- MachineProvider 只做 probe/exec/pty/心跳，不持有 ACP；ACP 仍由 AgentRuntime 负责。
- 环境配方只是 WorkspaceProvider 的一种实现；V0.2 只做 Docker，配方必须可审计、可清理、可拒绝。
- 不引入 OpenClaw/Paperclip 或任何外部控制面；不为配对 runtime 预置第二套组织模型。

### 4.2 D9 边界

- V0.1 只做每 Agent 独立 home + AGENTS.md/MEMORY.md 有界摘要注入；技能包不在 V0.1 加载。
- 记忆不跨 Agent 共享，不自动整理；写入只经 host 工具，快照可审计，owner 可清理。
- 记忆不能授予权限；技能包在 V0.2 单独引入，必须有 manifest、权限声明与审计。
- 摘要注入默认 4 KB、上限 16 KB；不注入密钥/完整环境变量/大段日志；内容按不可信数据处理。

## 5. 退出标准与未纳入项

V0.2 最小范围完成需同时满足：

1. A1–A5 的验收标准全部通过，且每项有可重复的 e2e 测试；
2. SSH 直连回归全绿，V0.1 的机器/Workspace/Task/Decision 行为不回退；
3. 所有新事件进现有事件模型，审计可回放；凭据不出现在持久化面；
4. 至少一次真实弱网/断线恢复演练，以及一次真实远端 runtime 上的 Agent 会话；
5. 文档更新：D8/D9 定稿、V0.2 运维/故障说明、迁移与回退到 SSH 的步骤。

本版不纳入：多组织/多租户、跨 runtime 调度与迁移、VM/云沙箱、技能市场、账户池、成本预算与计费、完整组织治理 UI。这些留待 V0.3 或按实际需求重新评估。
