## 3. 数据模型、事件与回放

SQLite 文件：`<state_dir>/monexus.db`（WAL、`busy_timeout`、`foreign_keys`）。

- `machines`：`id` 主键，显式目标字段（host/port/user/identity/
  use_ssh_config/host_key_policy/known_hosts_file）、`status`、`record_json`
  快照、`tombstoned`、时间戳。查询忽略 tombstone。
- `events`：`seq` 主键（全局单调）、`id`、`org_id`、`type`、`subject`、`ts`、
  `causation_id`、`correlation_id`、`idempotency_key`、`payload_json`；
  append-only，冲突不覆盖。
- `meta.last_seq`：记录已分配的最大序号，重启后从 `last_seq + 1` 继续，
  避免 heartbeat 被裁剪后序号回退。

写入路径：

1. `record_machine_event` 在 `BEGIN IMMEDIATE` 中提升 `meta.last_seq`、插入
   事件、更新/墓碑化机器行，然后提交；失败整体回滚。
2. 提交成功后才发布到内存 ring 并 fan-out 给订阅者——存储失败时订阅者
   不会看到未持久化的事件。
3. 启动时 `reconcile_projection` 重放全部 `machine.*` 事件，删除并重建
   machines 投影；事件是真相，投影只是缓存。

事件：

- `machine.registered`：新增记录（含完整 `machine` 快照）。
- `machine.connected`：从 unknown/offline 首次探测成功。
- `machine.probed`：每次探测成功；`status` 为 online 或 degraded。
- `machine.disconnected`：探测失败；记录离线与可读 `last_error`。
- `machine.removed`：墓碑事件，payload 携带 `machine_id`/`removed` 标记；
  回放时删除记录。

`machine.degraded` 不单独成事件：探测成功但 profile 缺少 os/arch/hostname
时，`machine.probed` 携带 `status=degraded`。

回放：`MachineProjection` 对事件按 last-record-wins 应用，`machine.removed`
写墓碑；`replay(events)` 不依赖数据库或网络，测试覆盖顺序、墓碑与非
machine 事件忽略。host 的 `events.subscribe --since` 由内存 ring（容量
256，启动时从 SQLite 预载）回放；持久事件表为后续全量游标保留。

## 4. Host RPC

所有请求带 `client_request_id`，复用 M1 的响应幂等缓存。机器 I/O（`ssh -G`、
`ssh` 探测）在 host mutex 外执行，完成后再读一次记录，避免把并发删除的
机器“复活”。

- `machine.add`
  - params：`name?`、`host`（必填）、`port=22`、`user=""`、`identity=""`、
    `use_ssh_config=true`、`host_key_policy=accept-new`、`known_hosts_file=""`、
    `client_request_id`。
  - 校验：host 只允许 hostname/IP 字符且不得以 `-` 开头；port 1–65535；
    user 只允许 `[A-Za-z0-9._-]`；policy 为 `accept-new|yes|no|config`。
  - 行为：读记录前先跑 `ssh -G` 得到生效配置（失败只记
    `ssh_effective_error`，不阻止注册）；生成 `mch_` id，写
    `machine.registered` 与投影，返回记录。
  - 结果：完整 `MachineRecord`。
- `machine.list`：返回 `{machines: [...]}`，按创建时间/id 排序，忽略墓碑。
- `machine.probe`
  - params：`machine_id`、`timeout_seconds`（1–120，默认 10）。
  - 重新解析 `ssh -G`，执行固定 probe 脚本；成功时更新
    `profile/ssh_effective/last_seen/status`，按 profile 完整性标
    online/degraded；失败时标 offline 并写可读原因。
  - 结果：`{machine, profile}`。
- `machine.remove`
  - params：`machine_id`；不存在返回 NotFound；成功写 `machine.removed`
    并墓碑化投影，返回 `{removed: true, machine_id}`。

错误：`machine_error(kind, message, detail)` → JSON-RPC error，`message`
为 `Unauthorized: ...` 等可读文本，`data.kind` 为稳定分类。Provider 映射：

| ProviderErrorKind | machine kind | 显示标签 |
| --- | --- | --- |
| AuthFailed | unauthorized | Unauthorized |
| ConnectTimeout | timeout | Timeout |
| NotFound | not_found | NotFound |
| Transport / SpawnFailed / NotConfigured | unreachable | Unreachable |
| HostKey | host_key | HostKeyRejected |
| RemoteExit | remote | RemoteError |
| Internal | internal | Internal |

## 5. SSH 探测与安全

- `SshTarget` 字段：host/port/user/identity/use_ssh_config/host_key_policy/
  known_hosts_file/timeout_seconds/extra_options。
- `ssh_argv`/`ssh_g_argv`：始终 `BatchMode=yes`、`ConnectTimeout=N`；
  `accept-new|yes|no` 映射 `StrictHostKeyChecking`，`config` 不添加（由
  `~/.ssh/config` 决定）；`known_hosts_file` 非空时加
  `UserKnownHostsFile=`。`use_ssh_config=false` 时加 `-F /dev/null`，机器
  记录是唯一真相。
- probe 脚本固定、无用户输入，经 `sh -lc '<script>'` 远端执行；只读字段：
  OS/ARCH/KERNEL/HOSTNAME/SHELL/CPUS/DOCKER/GUI/TOOL。`max_parallel` 取
  CPU 数并 clamp 到 64；`has_docker` 仅表示 CLI 存在；`has_gui` 是
  DISPLAY/WAYLAND/X11 socket 的保守启发式。
- 失败分类基于 ssh 退出码与 stderr（255 = 连接/认证失败，非远端命令
  退出码）；detail 保留 stderr，UI 只取首行。
- 测试从不修改用户 `~/.ssh`：回环用临时非 root sshd（随机端口、临时
  HOME/authorized_keys、`StrictModes no`），fake ssh 置于临时 PATH 前。
  注意 `ssh -G` 的 `~` 按 passwd home 解析而非 `$HOME`，因此冒烟脚本对
  每个 add 都显式传临时 `--known-hosts-file`。
- `install`/删除都只影响 `<state_dir>/monexus.db`；`host.json` 仍为 0600。

## 8. 已知限制 / 遗留

1. **手动探测**：M2 只在 `machine.probe` 时更新状态；没有后台定时探测/
   调度（M3 任务调度再引入心跳）。
2. **订阅回放缓冲**：`events.subscribe --since` 从 256 条内存 ring 回放
   （启动时由 SQLite 预载）；更老的事件仍在 `events` 表，但没有全量游标
   查询 RPC。
3. **`ssh -G` 的 home 语义**：OpenSSH 用 passwd home 解析 `~`，不跟随
   `$HOME`；涉及 known_hosts/identity 的测试必须显式传路径。
4. **幂等缓存仅在内存**：host 重启后同一 `client_request_id` 的重试可能
   再次执行；桌面每次命令使用新 id，不受影响。
5. **无远程文件/终端/Agent**：明确留给 M3/M4；Machines 页只做注册与探测。
6. **原生窗口未交互验证**：本机无 display，使用 `moon test` 与
   `moui screenshot`；窗口交互需图形环境。
7. **host key policy `config`**：只在 `use_ssh_config=true` 时推荐使用；
   关闭 config 后该策略不添加 `StrictHostKeyChecking`，行为由 ssh 默认值
   决定。
